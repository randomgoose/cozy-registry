# Homepage Optimization Prep Spec

本文用于在不改代码的前提下，为首页优化准备一套可执行的输入材料、评估标准与落地节奏。

目标是先把“要优化什么、为什么优化、如何判断有效”定义清楚，再进入设计和开发。

## 1. Problem Statement

当前首页优化通常会遇到以下问题：

- 目标不聚焦（既想讲品牌，又想讲功能，又想促转化）
- 输入材料不完整（缺少用户分层、价值主张、证据素材）
- 缺少统一验收口径（上线后无法判断优化是否有效）

结果是容易产生“视觉更新很多，但业务效果不确定”的情况。

## 2. Goals

- 在开发前准备完整的首页优化输入包
- 明确首页一屏到全页的信息优先级
- 设定可量化的成功指标与实验口径
- 降低跨角色沟通成本（产品、设计、前端、增长）

## 3. Non-Goals

- 本文不包含具体 UI 稿或代码实现
- 本文不替代详细 PRD 与交互说明
- 本文不直接定义最终视觉风格

## 4. Optimization Scope Definition

开始前先明确本轮优化范围：

- 页面范围：仅首页（`/`）还是包含导航、全局 footer
- 目标动作：注册、登录、创建项目、查看文档、试用 demo 等
- 用户范围：新访客、回访用户、团队采购决策者、开发者
- 设备范围：桌面优先或移动端并行
- 语言范围：中文、英文或双语

建议输出一个 1 页 scope 声明，避免中途扩 scope。

## 5. Core Inputs To Prepare

### 5.1 用户与场景输入

至少准备：

- Top 3 用户画像（例：设计师、前端开发者、技术负责人）
- 每类用户访问首页的首要任务（JTBD）
- 他们最关心的疑问（如“是否可私有部署”“是否 AI 可直接消费”）
- 他们最可能流失的原因（如“看不懂差异化价值”）

### 5.2 价值主张输入

至少准备：

- 一句话价值主张（15 秒内可理解）
- 三条核心价值（每条对应一类用户收益）
- 与替代方案对比（手写组件库、内部脚手架、公开市场）
- 不承诺项（避免过度营销）

### 5.3 证据与信任输入

至少准备：

- 真实产品截图或流程图（发布、预览、安装、升级）
- 可验证能力清单（MCP 能力、artifact 模型、权限边界）
- 客户/团队反馈摘录（如有）
- 安全与部署信息（私有化、权限、审计等）

### 5.4 信息架构输入

至少准备：

- 首页区块清单（Hero、价值点、能力说明、案例、FAQ、CTA）
- 每个区块的单一目标（只做一件事）
- 每个区块的主文案与备选文案（A/B 版本）
- 页面叙事顺序（从“是什么”到“为什么可信”再到“下一步”）

### 5.5 设计与品牌输入

至少准备：

- 品牌语气（专业/亲和/技术导向）
- 视觉约束（色板、字体、间距、动效强度）
- 可复用设计 token 与组件范围
- 竞品参考板（做法可借鉴 vs 必须避免）

### 5.6 数据与追踪输入

至少准备：

- 当前基线数据（PV、跳出率、首屏停留、CTA CTR、转化率）
- 事件埋点字典（点击、滚动深度、表单提交、跳转）
- 漏斗定义（访问 -> 关键行为 -> 注册/留资）
- 分段维度（来源渠道、设备、地域、新老访客）

## 6. Homepage Content Blueprint (Draft)

推荐先按以下顺序准备内容草案：

1. Hero
   - 目标：15 秒内解释产品价值与目标用户
   - 准备项：主标题、副标题、主 CTA、次 CTA、产品视觉
2. Why Cozy Registry
   - 目标：明确与替代方案的差异
   - 准备项：3-4 条差异化能力 + 每条证据
3. Workflow / How it works
   - 目标：降低理解成本，说明端到端流程
   - 准备项：3-5 步流程图、每步输入输出
4. Use Cases
   - 目标：让不同角色快速自我映射
   - 准备项：按角色分组的场景卡片
5. Trust / Deployment / Security
   - 目标：降低组织采购和接入顾虑
   - 准备项：部署模式、权限能力、合规信息
6. FAQ
   - 目标：提前回答高频阻塞问题
   - 准备项：10-15 个问题，按“接入/成本/安全/迁移”分组
7. Final CTA
   - 目标：引导明确下一步动作
   - 准备项：单一主动作 + 风险逆转文案（例如“先试用再接入”）

## 7. Success Metrics And Guardrails

### 7.1 North-star Metrics

- 首页到目标动作转化率（主指标）
- Hero 主 CTA 点击率
- 关键区块阅读完成率（滚动 + 停留）

### 7.2 Guardrail Metrics

- 页面性能不退化（LCP、INP、CLS）
- 跳出率不恶化
- 低意图点击率不显著上升（避免“高点击低转化”）

### 7.3 Qualitative Signals

- 用户是否能复述“一句话价值主张”
- 访谈中对“适用场景”和“可信性”的理解是否提升

## 8. Experiment Plan (Before Dev)

上线前先定义实验策略：

- 实验对象：标题文案、CTA 文案、区块顺序、证据呈现方式
- 最小实验单元：每次只改一类变量
- 判定周期：至少覆盖完整业务周
- 样本阈值：预估最小可检验样本量
- 终止条件：达到显著收益/无效/负向影响

## 9. Collaboration Model

建议分工：

- Product：目标、范围、指标、实验口径
- Design：信息架构、视觉策略、组件规范
- Engineering：可行性评估、性能预算、埋点落地
- Growth/Marketing：流量质量、文案验证、渠道映射

建议每周固定一次 30-45 分钟同步，追踪输入缺口与风险。

## 10. Definition Of Ready (DoR)

进入设计/开发前，以下清单需全部满足：

- [ ] 首页目标动作已单点确定（最多 1 主 + 1 次）
- [ ] 用户分层与首页任务清晰
- [ ] Hero 文案与价值主张完成评审
- [ ] 每个区块有明确目标和证据素材
- [ ] 指标、埋点、漏斗定义完成
- [ ] 性能预算与可访问性要求明确
- [ ] 实验计划和回滚条件明确

## 11. Risk List

常见风险与对应缓解：

- 目标过多 -> 强制排序，只保留最重要动作
- 文案抽象 -> 每条主张必须绑定证据
- 区块过长 -> 每屏只传达一个核心信息
- 过度动效 -> 预设性能预算与降级方案
- 指标缺失 -> 先补埋点再改页面

## 12. 2-Week Prep Timeline (Template)

### Week 1

- D1-D2：目标与范围确认、用户分层
- D3-D4：价值主张与内容草案
- D5：指标和埋点方案评审

### Week 2

- D1-D2：信息架构与低保真框架
- D3：跨角色评审（产品/设计/工程/增长）
- D4：实验计划冻结
- D5：DoR 检查并进入实现阶段

## 13. Deliverables Checklist

本轮建议至少产出以下文档/资产：

- 首页优化目标卡（1 页）
- 信息架构草图（区块顺序 + 目标）
- 文案包（主文案 + 备选文案）
- 证据素材包（截图、案例、FAQ）
- 指标与埋点定义表
- 实验计划与验收标准
